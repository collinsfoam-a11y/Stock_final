## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. Ensure you calculate an accurate `estimatedItemSize` by inspecting the item's layout and styles (padding, margins, font sizes) rather than guessing.
## 2024-05-25 - [VirtualList Verification & Safe Refactoring]
**Learning:** React Native's standard `FlatList` can be directly replaced by `VirtualList` to improve performance, but it is critical to verify the presence of `VirtualList` in `components/common` and carefully map properties like `estimatedItemSize` (instead of `getItemLayout`). Always run `pnpm typecheck` and `pnpm test` after these structural DOM component swaps, as isolated component tests will break if standard layout properties are blindly ported without ensuring correctness.
**Action:** When asked to optimize React Native lists with `VirtualList`, ensure exact file locations (like `@/components/common/VirtualList`), properly assign `estimatedItemSize`, and execute full testing via `pnpm` before assuming the drop-in replacement was completely transparent.
