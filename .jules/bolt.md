## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. Ensure you calculate an accurate `estimatedItemSize` by inspecting the item's layout and styles (padding, margins, font sizes) rather than guessing.
## 2024-05-25 - [VirtualList in Dropdowns vs Full-page Tables]
**Learning:** `FlashList` (used in `VirtualList`) does not support shrink-wrapping dynamic content heights. When replacing `FlatList` in dropdowns like `SearchAutocomplete` that must adjust height based on dynamic result counts, `VirtualList` collapses or breaks layout. It is also risky to replace if keyboard navigation relies on `listRef.current?.scrollToIndex(...)` because `VirtualList` might not forward or implement the exact same ref methods as `FlatList`.
**Action:** Do not use `VirtualList` for dropdowns, popovers, or any container that needs to shrink-wrap its content (use `ScrollView` or `FlatList`). Always carefully verify if `listRef` is used for auto-scrolling before replacing `FlatList`. It is much safer to optimize full-page, fixed-container lists (like paginated admin tables).
